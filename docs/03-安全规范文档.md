# 安全规范文档：AmpMySQL RPC 数据库代理

> 版本：v1.0 ｜ 状态：阶段 0 交付物 ｜ 红线条款，评审通过后强制执行

## 1. SQL 注入防护（红线）

1. **所有 SQL 必须预编译绑定**：RPC 层只接受含 `?` 占位符的 SQL 与参数数组，由 amphp/mysql 走 prepared statement 协议；
2. **网关内置 SQL 模板**：前端请求只传业务参数，SQL 模板由 Webman 网关代码硬编码管理，前端传入的任何 "sql" 字段一律忽略/拒绝；
3. RPC 服务侧仍保留 `sql` 入参（供网关传模板），但生产可开启模板白名单模式（二期）进一步收紧；
4. bindings 元素仅允许标量 / null，对象、数组一律 -32602 拒绝。

## 2. 网络边界

1. RPC 端口（9501）只在内网开放，禁止公网暴露；
2. 生产环境通过防火墙/安全组限制来源 IP 仅为 Webman 网关节点；
3. 二期增加 RPC Token 鉴权，一期以内网隔离为信任边界。

## 3. 权限最小化

1. MySQL 账号仅授予业务库 DML 权限（SELECT/INSERT/UPDATE/DELETE）；
2. 禁止 DDL、FILE、SUPER 权限；
3. 连接池上限防止单 RPC 实例打满数据库连接。

## 4. 资源保护

1. RPC 层限流：并发 SQL 上限 + 排队超时（-32002），过载快速失败保护 MySQL；
2. 单条 SQL 超时（默认 2s）防慢查询拖垮连接池；
3. 单行报文 1 MiB 上限防内存攻击；
4. 网关侧简易熔断：失败率超阈值直接降级，不再发起 RPC。

## 5. 幂等与重试

1. 写操作禁止自动重试（非幂等风险）；
2. 写操作必须携带业务幂等 key（request-id 落库唯一索引兜底）；
3. 只读查询仅瞬态连接错误重试 1 次。

## 6. 日志与审计

1. 两侧日志统一携带 requestId，字段规范见阶段 3 文档；
2. SQL 与 bindings 记录入日志（内网系统，用于排障）；生产可选脱敏开关；
3. 异常与超时必须记录 error 字段，不得吞异常。

## 7. 进程与部署

1. AmpRPC 服务由 supervisor / docker 托管，异常自动重启；
2. 优雅停机：SIGTERM 触发停止接新连接 → 处理完存量请求 → 关闭连接池退出；
3. 回滚开关：Webman 配置一键切回同步 PDO 路径。

# Webman + workerman-jsonrpc + AmpPHP amphp/mysql 数据库RPC代理方案开发计划

> 版本：v1.0 ｜ 编写日期：2026-11-25
> 目标：在不引入 Swoole/Swow 的前提下，让原生 Workerman（libevent）Webman 服务具备数据库 IO 并发能力

---

## 一、架构总览

```
客户端 HTTP 请求
      ↓
Webman HTTP 网关（Workerman + libevent 事件循环）
      ↓  TCP JSON-RPC 异步客户端（workerman/jsonrpc）
AmpPHP TCP RPC 服务（独立进程/独立容器，libev 事件循环）
      ↓  amphp/mysql 异步连接池
    MySQL
```

核心特性：

1. Webman 主线程非阻塞，回调驱动，单进程可并发处理 HTTP 请求；
2. AmpPHP 基于 libev 事件循环，amphp/mysql 异步执行 SQL，内置连接池；
3. 两套事件循环通过 TCP 边界隔离，互不干扰，**不依赖 Swoole/Swow 扩展**；
4. 协议：JSON-RPC 2.0，内网 TCP 通信，低延迟。

适用场景：不想引入 Swoole 扩展，希望在原生 Workerman 上获得数据库 IO 并发能力。

缺点：回调式异步，代码可读性与调试链路更复杂；多一层 TCP 网络开销；维护成本高于 Swoole 协程方案。

## 四、风险清单

1. **回调地狱**：Webman 侧为回调驱动异步，无法像协程一样同步 `await` 取结果，业务代码需改造为回调风格；
2. **链路丢失**：RPC 超时、Amp 服务宕机必须由超时回调兜底，否则连接悬挂、fd 泄漏；
3. **粘包**：`workerman/jsonrpc` 底层已封装换行分隔分包，无需自行实现；
4. **幂等**：写入类 SQL 必须携带 request-id 做幂等控制，禁止盲目重试；
5. **跨循环误用**：不得在 Webman 回调中执行同步阻塞 IO（PDO、file_get_contents、Guzzle 等）。

## 八、阶段 2：Webman 网关改造（1.5 天）

### 2.1 安装依赖


### 2.2 RPC 客户端封装

- 配置远端地址：`tcp://amp-mysql-rpc:9501`，连接池、超时 3s
- 封装 `rpcQuery()` / `rpcExecute()` 两个方法
- 自动生成全局唯一 requestId，用于链路追踪
- 回调结构：成功回调、失败回调、超时回调
- 注意：回调执行在 Webman libevent 主线程，可安全操作 `$connection` 对象

### 2.3 Webman HTTP 业务示例

```php
$http->onMessage = function ($conn, $req) use ($rpcClient) {
    $rpcClient->query(
        "SELECT * FROM user WHERE id=?",
        [$req->get('id')],
        // 成功回调
        function ($data) use ($conn) {
            $conn->send(json_encode(['code' => 0, 'data' => $data]));
        },
        // 失败回调
        function ($err) use ($conn) {
            $conn->send(json_encode(['code' => -1, 'msg' => $err]));
        }
    );
    // onMessage 直接返回，释放事件循环，可继续接收新请求
};
```

### 2.4 基础能力补齐

1. 请求日志：携带 requestId，打通 Webman 与 AmpRPC 两侧日志
2. 超时兜底：`workerman/jsonrpc` 内置超时，超时触发失败回调并返回 504
3. 参数校验：网关层禁止直接接收原始 SQL，使用预定义 SQL 模板
4. 本地联调：docker-compose 拉起 webman + amp-mysql-rpc + mysql 三件套

### 3.2 容错策略

1. **Amp 服务下线**：RPC 客户端触发失败回调，网关返回服务不可用；
2. **MySQL 断开**：Amp 连接池自动重连；
3. **限流**：Amp 侧增加最大并发 SQL 限制，保护 MySQL；
4. **只读 SQL 重试**：Amp 层最多重试 1 次，写 SQL 禁止重试；
5. **简易熔断**：Webman 侧失败计数器，高失败率直接降级返回。

### 3.3 监控指标

- RPC 请求量、失败率、超时率
- SQL 耗时 P95
- Amp 侧 MySQL 活跃连接数

## 十四、备选技术复盘

**本方案优势**：无 Swoole 依赖，原生 Workerman + libevent，内网 TCP 低延迟，单进程具备 DB 并发能力。

**本方案劣势**：回调异步，可读性差、调试困难，多一层 TCP 转发损耗，自研组件长期维护成本高。

**备选方案**：Webman 切换 Swoole 协程驱动，同步写法 + 底层 Hook，开发量可直接砍掉一半以上。若团队能接受 Swoole 扩展，该方案性价比更高。
